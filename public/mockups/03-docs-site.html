Data fetching

Fetch data on the server by default, stream it to the client as it resolves, and revalidate on a schedule or on demand — without writing an API layer in between.

Fetching in a server component

Server components run only on the server, so they can talk to your database or an internal service directly. The fetch call is memoized per request, which means calling it in two components does not fire two requests.

app/projects/page.tsxCopy
export default async function Page() {
  const res = await fetch('https://api.atlas.dev/projects', {
    next: { revalidate: 3600, tags: ['projects'] }
  })
  const projects = await res.json()

  return <ProjectGrid items={projects} />
}
Good to know

Requests made during a single render pass are deduplicated automatically. You do not need a client-side cache to avoid duplicate calls.

Cache options

Every request carries a cache directive. These are the four you will reach for most often:

OptionScopeBehaviour
force-cacheBuildCached indefinitely until the next deploy or an explicit purge.
no-storeRequestBypasses the cache entirely; the response is never reused.
revalidate: nTimeServes the cached copy, refreshing in the background after n seconds.
tags: [...]On demandPurged by calling revalidateTag() from a server action or webhook.
